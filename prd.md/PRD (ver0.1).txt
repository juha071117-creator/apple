# 스터디메이트(StudyMate) 제품 요구사항 문서(PRD)

**작성 근거:** 7주차 기획서, 9주차 프로젝트 기획서 ver(0.2), 실습 1~3
**현재 상태:** 프로젝트 선정과 기능·화면 설계 완료. 웹 MVP 작동 및 사용자 테스트는 미확인.

## 1. 프로젝트 소개

- **서비스명:** 스터디메이트(StudyMate)
- **유형:** 모델 구현 실습 중심
- **형태:** GPT를 활용한 웹 서비스
- **목표:** 대학생이 입력한 학습정보로 맞춤형 1주 학습계획을 제공한다.
- **확장 구상:** 서로 다른 대학의 비슷한 과목 학습계획을 공유·열람한다.

## 2. 사용자·문제·가치

- **사용자:** 학업·시험·개인 일정을 함께 관리하는 대학생.
- **문제:** 과제와 시험, 개인 일정이 겹치면 공부 우선순위를 정하기 어렵다.
- **예상 가치:** 공부 가능 시간에 맞는 계획으로 공부 순서를 정하도록 돕는다.
- **확인한 사실:** 4주차에 대학생 시간관리·학업 지연에 관한 선행연구 조사 기록이 있다.
- **검증할 가설:** 실제 대학생의 계획 수립 부담이 줄어드는가? 다른 대학의 유사 과목 계획이 도움이 되는가?
- **한계:** 목표 사용자를 대상으로 한 직접 설문·면담 결과는 미확인이다.

## 3. 만들 범위

| 우선순위 | 기능 |
| --- | --- |
| Must | 학습정보 입력, GPT 1주 계획 생성, 결과 표시, 일정 충돌 검증 |
| Should | 입력값 수정·재생성, 필수 입력·연결 오류 안내 |
| Could | 계획 복사, 유사 과목 학습계획 공유·열람 |
| Won't (이번 MVP) | 개념 설명·문제 힌트, 여러 과목 장기 일정 통합 |
- 입력 대상으로 기획된 정보는 과목·시험일·공부 가능 시간·교안 파일·커리큘럼·교수님의 시험 방식 등이다.
- **팀 결정 필요:** 입력 항목별 필수 여부, 후순위 기능의 실제 구현 범위.
- 유사 과목 공유는 후속 확장안이며 이번 MVP의 필수 기능은 아니다.

## 4. 구조·사용 순서

| 화면 ID | 화면명 | 내용 |
| --- | --- | --- |
| S-01 | 학습정보 입력 | 과목·시험일·공부 가능 시간 등 입력 |
| S-02 | 1주 학습계획 결과 | GPT 계획 표시, 날짜별 학습 내용·시간, 일정 충돌 확인 |
| S-03 (추후) | 유사 과목 계획 공유·열람 | 다른 대학의 비슷한 과목 계획 참고 |

**사용 순서:** 학습정보 입력 → GPT 조건 분석·계획 생성 → 결과 화면 표시 → 학생이 일정 충돌과 계획 정확성 확인.

## 5. 기능 설명

| 기능 | 완료 조건 |
| --- | --- |
| 학습정보 입력 | 기획한 학습정보를 입력할 수 있다. |
| GPT 계획 생성 | 입력 조건을 반영한 1주 계획이 생성된다. |
| 결과 표시 | 날짜별 학습 시간과 내용을 볼 수 있다. |
| 일정 충돌 검증 | 공부 가능 시간 밖에 배치된 일정을 찾아 기록할 수 있다. |
| 입력 수정·재생성 (Should) | 입력 조건을 바꾸어 새 계획을 생성할 수 있다. |
| 오류 안내 (Should) | 필수값 누락·GPT 연결 실패 시 메시지가 표시된다. |
| 계획 복사 (Could) | 계획 텍스트를 복사할 수 있다. |
| 유사 과목 공유 (Could) | 공유에 동의한 계획만 검색·열람할 수 있다. 개인 일정·교안 원문·시험 세부정보는 공개하지 않는다. |

위 조건은 **구현 목표**이며 달성 여부는 아직 확인되지 않았다.

## 6. 테스트 방법·성공 기준

- **테스트 방법:** 대학생이 정보를 입력하고 계획 생성 여부를 확인한다.
- 생성 계획을 시험일·공부 가능 시간과 비교한다.
- 일정 충돌과 명백한 학습 오류를 찾아 기록한다.
- 결과의 이해도와 실용성에 대한 학생 의견을 기록한다.
- **잠정 성공 기준:** 1주 계획이 생성되고, 입력 조건을 반영하며, 결과를 이해할 수 있고, 발견된 오류를 기록할 수 있다.
- **팀 결정 필요:** 테스트 인원, 허용 오류 수, 성공률, 만족도 기준.
- **현재 상태:** 실제 기능 테스트 및 사용자 평가 결과 미확인.

## 7. 일정·담당·문제 대응

**기획서의 예시 일정(팀 확정 필요)**

| 시기 | 작업 |
| --- | --- |
| 9주차 | MVP 범위 확정 및 PRD 작성 |
| 10주차 | 웹 입력·결과 화면 및 GPT 연결 구현 |
| 11~12주차 | 계획 생성, 일정 충돌·정확성·사용자 테스트 |
| 13주차 | 오류 보완, 결과 정리 및 시연 준비 |

**담당:** 팀원별 역할 분담은 팀 결정 필요.
**도구·비용:** 개발 도구, GPT API 사용 방식·비용은 팀 결정 필요.

| 예상 문제 | 대응 계획 |
| --- | --- |
| GPT의 잘못된 학습 내용 | 입력정보 및 교재와 대조하고 오류를 기록한다. |
| 일정 충돌 | 공부 가능 시간과 계획을 비교한다. |
| 개인정보 노출 | 불필요한 개인정보 수집을 줄이고 공유 동의를 확인한다. |
| 저작권 문제 | 교안·교재 출처와 이용 조건을 확인한다. |
| 불합리한 계획·편향 | 다양한 학습 조건으로 결과를 확인한다. |
| GPT 연결 장애·비용 | API 한도·연결 오류와 사용자 안내를 점검한다. |

대응 방법은 계획 단계이며 실제 적용 효과는 미확인이다.

## 확인한 사실과 검증할 가설

**확인한 사실:** 스터디메이트를 최종 선정했고, GPT 웹 서비스의 입력→처리→출력 흐름과 실습 1~3의 기능·화면 구조를 기획했다.

**검증할 가설:** 맞춤 계획이 학생에게 유용한가? 기존 GPT·일정 앱보다 나은가? 유사 과목 계획 공유가 도움이 되는가? 정해진 범위 안에서 구현할 수 있는가?

**팀 결정 필요:** 필수 입력 범위, 후순위 기능 포함 여부, 테스트 수치, 담당자, 실제 일정과 비용.
