# PRD (ver0.2)

**작성 근거** · 9주차 실습 4-PRD, 10주차 와이어프레임과 프로토타입, 11주차 수정 프로토타입

**현재 상태** · 11주차 HTML에서 로그인 상태별 홈, 회원가입, 로그인·로그아웃, 계정별 계획 확인을 시연할 수 있다. 계획 배치는 입력 조건에 따라 규칙 기반으로 동작하며, GPT 연동은 제품 구현 목표다.

## 1. 프로젝트 소개

- **서비스명** · 스터디메이트(StudyMate)
- **유형** · 모델 구현 실습 중심
- **형태** · GPT를 활용하는 맞춤 학습계획 웹 서비스
- **목표** · 대학생이 한 과목의 시험일과 공부 가능 시간에 맞춰 1주 학습계획을 만들고, 다시 방문했을 때 자신의 계획을 확인할 수 있도록 한다.
- **확장 구상** · 서로 다른 대학의 비슷한 과목 학습계획을 공유하고 참고할 수 있도록 한다.

## 2. 사용자·문제·가치

- **사용자** · 학업·시험·개인 일정을 함께 관리하는 대학생.
- **문제** · 과제와 시험, 개인 일정이 겹치면 무엇을 언제 공부할지 정하기 어렵다.
- **예상 가치** · 공부 가능한 시간에 맞춰 학습량과 순서를 정할 수 있다. 첫 방문자는 예시 계획으로 결과 형태를 살펴보고, 가입한 사용자는 자신이 만든 계획을 다시 열 수 있다.
- **확인한 사실** · 기존 기획에서 대학생의 시간 관리와 학업 지연에 관한 선행연구를 조사했다. 실제 사용자에게 계획 수립 부담이 줄어드는지는 평가가 필요하다.

## 3. 만들 범위

| 우선순위 | 기능 |
| --- | --- |
| Must | 로그인 상태별 홈, 회원가입, 아이디·비밀번호 로그인과 로그아웃, 학습정보 입력, 맞춤 1주 계획 생성, 결과 표시, 일정 충돌 검증, 계정별 계획 저장·확인 |
| Should | 입력값 수정·재생성, 필수 입력 및 가입·로그인 오류 안내, GPT 연동 시 연결 오류 안내 |
| Could | 계획 텍스트 복사, 유사 과목 계획 검색·공유 |
| Won’t (이번 MVP) | 개념 설명·문제 힌트, 여러 과목의 장기 일정 통합 |
- 한 과목의 과목명, 계획 시작일, 시험일, 학습 범위, 요일별 공부 가능 시간을 입력한다. 개인 일정과 교안 첨부 등 추가 항목은 기존 입력 화면에서 선택할 수 있다.
- 11주차 시연은 브라우저에 계정과 계획을 저장한다. 서버 인증과 기기 간 동기화는 후속 범위다. 공유 화면에서 예시와 브라우저에 저장된 공유본을 볼 수 있으며, 여러 사용자 간 공유는 확장 기능으로 다룬다.

## 4. 구조·사용 순서

| 화면 ID | 화면명 | 내용 |
| --- | --- | --- |
| S-00 | 홈 | 비로그인 상태에서는 서비스 소개, 로그인·회원가입, 자료구조 1주 예시와 다른 계획 둘러보기를 제공한다. 로그인 상태에서는 계획 유무에 따라 ‘첫 학습계획 만들기’ 또는 ‘내 계획 보기’를 표시한다. |
| S-01 | 학습정보 입력 | 과목명, 시험일, 공부 가능 시간과 개인 일정 등을 입력한다. |
| S-02 | 1주 학습계획 결과 | 날짜별 학습 내용·시간과 충돌 건수를 표시한다. 내용을 확인한 뒤 저장할 수 있다. |
| S-03 | 계획 공유·열람 | 예시와 저장된 공유본을 과목별로 찾아볼 수 있다. 대학 간 공유는 후속 확장 범위다. |
| S-04 | 로그인 | 아이디와 비밀번호를 입력한다. 성공하면 로그인 상태의 홈으로 이동한다. |
| S-05 | 회원가입 | 아이디, 비밀번호, 비밀번호 확인을 입력한다. 가입하면 아이디가 채워진 로그인 화면으로 이동한다. |
- **신규 사용자** · 비로그인 홈 → 회원가입 → 로그인 → 첫 학습계획 만들기 → 학습정보 입력 → 결과 확인·저장.
- **기존 사용자** · 비로그인 홈 → 로그인 → 내 계획 보기 → 결과 확인.
- 비로그인 상태에서 학습계획 또는 일정 메뉴를 누르면 로그인 화면이 열린다. 상단 ‘스터디메이트’를 누르면 현재 상태의 홈으로, ‘로그아웃’을 누르면 비로그인 홈으로 이동한다.

## 5. 기능 설명

| 기능 | 완료 조건 |
| --- | --- |
| 로그인 상태별 홈 | 로그인 전에는 예시를 볼 수 있다. 가입 후 처음 로그인하면 ‘첫 학습계획을 만들어 볼까요?’가 표시된다. 계획을 만든 계정에는 ‘내 계획 보기’가 표시된다. |
| 회원가입 | 영문·숫자·밑줄·하이픈으로 된 3~24자 아이디와 8자 이상 비밀번호로 가입할 수 있다. 중복 아이디나 비밀번호 확인 불일치가 있으면 안내를 표시한다. |
| 로그인·로그아웃 | 가입한 정보와 일치할 때 로그인한다. 일치하지 않으면 화면에서 다시 입력할 수 있다. 로그아웃하면 비로그인 홈을 표시한다. |
| 학습정보 입력·수정 | 필수 학습정보를 입력할 수 있고, 결과 화면에서 입력으로 돌아가 계획을 다시 만들 수 있다. |
| 1주 계획 생성 | 시험일 이전에 최대 7일의 학습계획을 생성한다. 11주차 HTML은 입력된 공부 가능 시간에 따라 규칙 기반으로 배치한다. |
| 결과 표시·일정 충돌 검증 | 날짜별 학습 시간과 내용을 볼 수 있고, 공부 가능 시간과 개인 일정에 어긋나는 배치가 있는지 확인할 수 있다. |
| 계정별 계획 저장·확인 | 저장한 계획을 같은 브라우저에서 해당 계정으로 다시 로그인해 열 수 있다. 다른 계정으로 로그인하면 그 계정의 계획만 표시한다. |
| 계획 공유·열람 | 비로그인 사용자도 예시와 공유용 계획을 열람할 수 있다. 공유본에 개인 일정, 실제 날짜·시간, 교안 및 시험 세부정보를 포함하지 않는다. |

## 6. 테스트 방법·성공 기준

- **기능 테스트** · 신규 가입, 중복 아이디, 비밀번호 확인 불일치, 잘못된 로그인 정보, 로그아웃, 계정별 계획 분리를 코드 테스트로 확인했다.
- **시연 확인 방법** · 새 계정으로 가입·로그인해 첫 계획을 만든다. 결과를 저장한 뒤 로그아웃하고, 같은 계정에서 계획이 다시 열리는지 확인한다. 두 번째 계정에서 첫 번째 계정의 계획이 표시되지 않는지도 확인한다.
- **계획 검토 방법** · 시험일, 공부 가능 시간, 개인 일정과 결과를 비교한다. 날짜별 공부량을 이해하기 쉬운지, 실제로 따라갈 수 있는지 사용자 의견을 기록한다.
- **잠정 성공 기준** · 회원가입부터 계획 저장·재열람까지 완료할 수 있고, 예외 입력에는 안내가 표시되며, 계획이 입력된 시간 조건에 맞는다.
- **팀 결정 필요** · 사용자 테스트 인원과 성공률·만족도 기준. 대학생 대상 사용성 평가 결과는 아직 확인되지 않았다.

**담당과 비용** · 후속 개발 담당자, GPT API 연동 방식과 비용은 팀에서 결정한다.

| 예상 문제 | 대응 계획 |
| --- | --- |
| 잘못된 계정 입력 | 중복 아이디, 비밀번호 확인 불일치, 로그인 실패 안내를 해당 입력 화면에 표시한다. |
| 일정 충돌 | 시험일과 공부 가능 시간, 개인 일정을 결과와 대조한다. |
| 계정·계획 저장 범위 혼동 | 현재 시연에서는 같은 브라우저의 계정별로 계획을 확인할 수 있음을 안내한다. |
| 개인정보·저작권 | 공유 전에 공개 항목을 확인하게 하고, 개인 일정과 교안 정보를 공유본에서 제외한다. 교안 이용 권한을 확인한다. |
| GPT 학습 내용 오류와 연결 장애 | GPT 연동 후 학습 내용을 입력 자료와 비교하고, 연결 실패 시 오류 안내를 점검한다. |

## 확인한 사실과 검증할 가설

- **확인한 사실** · 11주차 HTML에 로그인 상태별 홈, 회원가입, 아이디·비밀번호 로그인, 계정별 계획 확인을 구현했다.
- **검증할 가설** · 비로그인 홈에서 예시를 본 사용자가 기능을 쉽게 이해하는가? 가입한 대학생이 첫 계획을 만들고 이후 다시 열어 활용할 수 있는가? 맞춤 계획이 공부 순서를 정하는 데 도움이 되는가?
- **팀 결정 필요** · 사용자 테스트 기준, GPT 연동 범위, 실제 계정 인증과 대학 간 계획 공유의 구현 시점.
